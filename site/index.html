A browser agent that builds clinical studies on any eSource platform

Take-Home 1a for Intake AI. One extension, one input file, no platform-specific selectors: the agent reads the page semantically, calibrates itself against whatever element library it finds, builds all 4 visits, 28 forms, and 195 fields, and escalates anything it is not sure about to a human before committing.

How the agent works

PerceiveSnapshots the page as affordances: role, accessible name, visible text, containment. No CSS selectors, no ids, no hardcoded labels.
DecideRanks candidates against concept vocabularies (visit, document, save, values, condition) and acts only on positive-margin matches.
ActClicks and types with synthetic events, re-resolving every control at act time because platforms re-render freely.
ConfirmReads back everything after saving: reopen the form, select every field, compare against the input, repair, re-audit.

Type mapping is an experiment, not a string match

On entering the first form designer, the agent clicks every palette entry once and watches what happens: does a coded values editor appear? Min and max inputs? A formula box? What does the preview control render? The observed behavior places each entry in a semantic group, the label vocabulary disambiguates within the group, and the margin between the top two candidates becomes a confidence score. Probes are discarded before any real field is built.

"Check List" vs "Checkbox"

The classic trap. Probing shows one grows a coded values editor and the other renders a single tick with no values section. The names never decide it alone.

"Save" vs "Save As Template"

The save control is confirmed by a persistence probe: build a sentinel field, click a candidate, leave, come back. If the sentinel is gone, that button was lying.

The human gate

The agent never guesses silently. Low-confidence type mappings, missing controls (no repeating toggle, no visible range inputs), skip-logic controllers it cannot find, and audit mismatches that survive a repair round all pause the run and surface a card with the question, the evidence, and concrete options. Confident work proceeds automatically; on the two mocks in this repo a full clean run needs zero interventions, so the reviewer only ever sees real problems.

Evidence that it generalizes

Mock B is a second eSource I wrote to be different everywhere: encounters instead of visits, instruments instead of source documents, a Question Palette with names like "Tally Counter" and "Moment Picker", card layouts with role="button" divs instead of tables and buttons, modal dialogs, a "Commit Changes" save with a fake "Store Draft Locally" beside it, and a full re-render on every interaction. Mock A2 is Mock A with its element library renamed ("Select One (Menu)", "Fraction Number", "Tick Box"), the save button renamed "Apply Changes" and moved, and the schedule screen retitled. The agent discovered the new save control by persistence probing and remapped all thirteen types, escalating the three it was least sure about.

Getting there surfaced real failures along the way (wrong inputs renamed, an over-eager repair loop that once deleted a field, palette detection missing card-based layouts). Those runs and what was learned from them are written up honestly in the repo's README, together with the failure modes that remain.
